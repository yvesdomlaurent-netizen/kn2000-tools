# Changelog — KN2000 Tools

Historique des versions des outils Web MIDI pour Technics SX-KN2000.
Format inspiré de [Keep a Changelog](https://keepachangelog.com/) — versions [semver-like] simplifiées (vMAJOR.MINOR.PATCH à la discrétion du projet).

Outils :
- **Sound Editor** — `sound-editor.html` — éditeur de sons Sound Memory (144 octets)
- **Panel Console** — `panel-console.html` — console de pilotage du clavier
- **Sauvegarde / Catalogue** — `backup.html` — dump et catalogue de l'état complet du clavier
- **APC Live** — `kn2000-apc-live-v2.html` — pilotage de scène temps réel : grilles d'accords, morceaux, parties

- **v2.7.2 — 🐛 blindage timing-aveugle du correctif v2.7.1 (retour terrain : « toujours rien dans les choix de ports MIDI » alors que la v2.6.33 marche sur le même Edge)** : un timer 0 ms n'est PAS une garantie — le parseur peut rendre la main ENTRE les deux blocs de script (page de 341 Ko livrée en morceaux réseau), et le timer expire alors AVANT le bloc 2 : même erreur TDZ. Trois balises de boot (`__b1end`, `__b2midi`, `__b2end`) rendent le prochain retour terrain décisif. - **v2.7.3 — 🐛 cause racine trouvée grâce aux balises v2.7.2 (retour terrain : « ⚠️ MIDI accessible mais bloc 1 : INTERROMPU · bloc 2 : PAS INITIALISÉ »)** : le calque du **Mode Scène** (`<div id="sceneFs">` et ses éléments scClose, scPrev, scNext, scFollow, scPlay, scTitle, scSec, scChords, scLyric, scBeats, scCount, scTempo) était déclaré **APRÈS les deux blocs `<script>`** de la page — or un élément situé après un bloc n'existe pas encore quand ce bloc s'exécute. Le bloc 1 plantait donc dès sa liaison du Mode Scène (`document.getElementById("scClose").onclick` → null), AVANT de définir `songs`/`SETLIST_V2` : le bloc 2 héritait d'une cascade TDZ et tombait à son tour, laissant `midiAccess2` en zone morte. Tous les symptômes terrain depuis la v2.7.0 s'expliquent d'un coup : page Morceaux vide, import muet, ports RX/TX jamais remplis, « Cannot access (…) before initialization » à chaque clic Connecter. Correctif : le calque sceneFs est DÉPLACÉ AVANT les scripts (zone parsée au moment de l'exécution) ; les correctifs v2.7.1 (setTimeout) et v2.7.2 (b2Wait + balises de boot) sont conservés comme ceintures de sécurité. Leçons : (a) auditer chaque `getElementById` contre la zone HTML située AVANT le script, pas contre le fichier entier ; (b) un harnais qui construit ses éléments depuis le fichier SOURCE complet masque ce type de bug — le modèle doit refléter le DOM réellement parsé ; (c) contrôlé négativement : le nouveau harnais fait crasher la v2.7.2 exactement à la ligne incriminée, et passe 23/23 sur la v2.7.3 (boot vierge seed 136 + MIDI prêt + ports remplis + Mode Scène ouvrable, import réel 274 morceaux → « 274 morceau(x) — 138 ajouté(s), 136 remplacé(s) », HEY JUDE 18 rangées + titre Scène, boot avec les 274 pré-stockés dans le pire cas de la course au démarrage).
