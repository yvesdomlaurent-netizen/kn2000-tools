💾 Sauvegarde / Catalogue — Aide / Help

💡 Depuis la v0.5.0 la page est organisée en trois onglets — 📡 Dumps (sauvegarde KN2000 → page), 📚 Catalogue (patches, tableau de bord, restauration) et 🗂️ Bibliothèque (master, imports/exports croisés, sons nommés). Cet outil catalogie l'état complet du clavier par dump handshake (protocole validé le 26/10/2026 avec la Panel Console v1.0.9 : exactement un ACK après chaque paquet reçu), puis exporte une sauvegarde JSON unique horodatée, décodable par une future appli Android de repli terrain.

🚀 Démarrage rapide

  1. Ouvrir la page dans Chrome, Edge ou Firefox 108+ desktop (Web MIDI avec sysex requis).
  2. Brancher l'interface MIDI USB (ex. Arturia MiniFuse) reliée au KN2000 par câble MIDI DIN — le KN2000 lui-même n'a pas d'USB, cliquer 🔄 Ports et choisir In/Out.
  3. Brancher l'interface, la page tente la connexion automatique avec les ports mémorisés ; sinon choisir In/Out puis 🔌 Connecter — le KN2000 est testé par un ping (DRQ 20 00 02) et les enables sont lus automatiquement une fois connecté (lecture seule, rien n'est écrit).
  4. Une fois la pastille ● connecté affichée : cliquer 🔄 Dumper sur l'aire voulue — le dump se lance directement, aucune préparation au clavier n'est nécessaire (découverte terrain du 26/10/2026 : la page SYSEX BULK DUMP du clavier n'a pas besoin d'être affichée).
  5. Une fois les aires voulues cataloguées, cliquer 💾 Cataloguer par aire (patch du catalogue) puis 💾 Exporter le catalogue (JSON) pour une copie fichier.
  6. Restaurer : onglet 📚 Catalogue → choisir l'aire et le mode (complet / différentiel) → ↩️ Restaurer (Sound Memory validée terrain ; voir « Catalogue & restauration » ci-dessous).

🗺️ Aires (Reference Guide p.24-27) — toutes validées terrain ✅

  • PANEL — ADR 40 00 00 — validé terrain : blocs 40 (1056/1088, écart 32 documenté) + 41 (8064/8064 = 24 Panel Memory × 336).
  • SOUND MEMORY — ADR 30 00 00 — validée terrain : entête 80 octets (bloc 30) + 36 sons × 144 octets (bloc 30#2, 5184/5184).
  • COMPOSER — ADR 50 00 00 — validée terrain : 37 920 octets (70 patterns).
  • SEQUENCER — ADR 60 00 00 — validée terrain : 3 blocs (256 + 768 + 2048 octets avec contenu).
💡 Découverte terrain 26/10/2026 : les dumps se lancent directement depuis la page — la page SYSEX BULK DUMP du clavier n'a pas besoin d'être affichée, aucun type à sélectionner. Le bouton « ▶ Enchaîner les aires restantes » propose 5 s de pause entre chaque aire.
⚠️ Le dump request utilise la forme validée sur le panel (ADR + SIZ 00 00 42) : les 4 aires répondent correctement avec cette constante (validé terrain 26/10/2026).

🤝 Protocole utilisé

Identique à la Panel Console v1.0.9 (validé terrain) : DRQ → le clavier envoie HRQ (21) → nous répondons HRT (22) → le clavier envoie HRT (22) → nous acquittons, puis exactement un ACK (f0 50 23 7e f7) après chaque paquet reçu : BTR (2D), chaque paquet CDD (7E) à checksum OK, EOK (27), END (28). Aucun re-DRQ automatique — un re-DRQ parasite relance la page BULK DUMP et contamine le handshake.

📄 Format du JSON exporté (kn2000-catalog-v1)

Le fichier kn2000-catalogue-AAAA-MM-JJ_HHhMM.json est auto-documenté (champ encodage) et pensé pour être décodé par une appli Android :

{
  "tool": "KN2000 Sauvegarde / Catalogue",
  "format": "kn2000-catalog-v1",
  "version": "0.2.2",
  "date": "2026-10-26T…ISO…",
  "keyboard": "Technics SX-KN2000",
  "enables": { "20 04 00": "01", … },
  "areas": {
    "panel": {
      "name": "PANEL",
      "adr": "40 00 00",            // aire demandée
      "dump_request_adr": "40 00 00",
      "date": "…ISO…",
      "finished": true,             // END reçu
      "blocks": [
        {
          "adr": "40",              // adresse du bloc (2D)
          "siz_annonce": 1088,      // SIZ du BTR (octets originaux)
          "octets_recus": 1056,
          "data": "0a0a0106…"       // hex minuscule, 2 chiffres/octet,
                                    // MSB d'abord ; "--" = octet manquant
        }
      ]
    }
  }
}
  • data contient les octets originaux dénibblisés (sur le fil MIDI ils voyagent nibblisés ×2 — Reference Guide p.22) ; siz_annonce compte les octets originaux.
  • Un octet manquant (paquet perdu ou bloc clôt avant SIZ) est noté -- : la chaîne garde toujours 2 × siz_annonce caractères, index calculable par index_octet × 2.
  • Blocs multiples à même adresse : une aire peut contenir plusieurs blocs de même adr (ex. Sound Memory : entête de 80 octets puis les sons 5184, tous deux adr: "30") — le champ seq (1, 2, …) donne l'ordre d'arrivée.
  • Exemple décodage Android : int b = Integer.parseInt(data.substring(i*2, i*2+2), 16); — "--" ⇒ octet inconnu.
💡 Le bloc 40 du panel s'arrête systématiquement à 1056/1088 octets (écart 32 constant observé sur toutes les captures et le terrain, sans conséquence) : les 32 octets manquants apparaissent en -- dans le JSON — c'est normal.

✉️ Import & envoi manuel vers le KN2000 — voir la page 🛠️ outils

L'envoi manuel bloc par bloc (adresses de base, N octets/trame, pause, mode sons) et la 🔍 comparaison manuelle ont déménagé dans la page outils techniques privée (tools.html, lien depuis la page principale) — ils servent à valider les aires une à une. La page principale reste dédiée aux sauvegardes et restaurations courantes.

La section 3 — Import catalogue & envoi recharge un JSON exporté par la page (format kn2000-catalog-v1) et écrit un bloc choisi vers le clavier, puis permet de vérifier par diff octet par octet.

  1. 📂 Importer le catalogue (JSON), choisir l'aire et le bloc.
  2. ✉️ Envoyer : deux modes — 36 sons (chaque son de 144 octets part en 2 trames ITW de 120 + 24 octets aux adresses 30 00 50 + n×90) ou trames de N octets à adresse de base incrémentée linéairement (défaut 30 00 50, N = 120 max, pause réglable).
  3. Observer les réponses du clavier (log) — première écriture bulk réelle, comportement inconnu : ACK ? silence ? ERR ?
  4. Attendre ~5 s, 🔄 re-dumper l'aire, puis 🔍 Comparer (diff octet par octet bloc importé vs re-dump).

Trame d'écriture ITW (2C) — miroir des ITR du clavier, format du Sound Editor. Limite terrain (bissection 26/10/2026) : 120 octets originaux max par trame (255 octets sur le fil — buffer 256 du clavier ; 121+ refusé, le clavier ne répond RIEN, il applique en silence) : f0 50 2c 01 18 10 A1 A2 A3 00 Sh Sl <nibbles> 00 CK f7 — SIZ sur 3 octets 7-bit (octets originaux), données nibblisées ×2 (Reference Guide p.22), CN = 00, CK = XOR du corps & 7f. Le Sound Editor écrivait octet par octet (60 ms) ; l'inconnue du test est la réaction du clavier aux trames multi-octets.

⚠️ L'envoi est une écriture réelle dans la mémoire du clavier. Test recommandé sur la Sound Memory (récupérable par la procédure usine). Un bloc contenant des octets manquants (--) est refusé.

📚 Catalogue & restauration (v0.4.0)

  1. 💾 Cataloguer (onglet Dumps) : le dernier dump d'une aire devient un patch du catalogue — nom automatique + date. Contenu identique au patch précédent → seule sa date est mise à jour ; contenu différent → nouvelle version. Les anciennes versions ne sont jamais écrasées (suppression explicite 🗑 uniquement).
  2. Tableau de bord (onglet Catalogue) : croisement par aire entre ce qui réside dans le KN2000 (dernier dump, persistant) et ce qui doit y aller (patch courant) : 🟢 conforme / 🟡 N octets différents / ❌ jamais dumpé — plus la date du dernier envoi vers le KN2000.
  3. 📂 Importer un catalogue : chaque aire d'un JSON kn2000-catalog-v1 devient un patch (dédupliqué par contenu). Les infos d'entête (blocs, tailles) et, pour la Sound Memory, les 36 noms de sons sont affichés sous chaque patch Sound.
  4. ↩️ Restaurer (Sound Memory, ✅ validée terrain) : Complet = entête 80 o + 36 sons en 73 trames ITW (120 o max/trame, pause 60 ms ≈ 5 s) ; Différentiel = ne renvoyer que les sons/entête qui diffèrent du dernier dump. Confirmation obligatoire — mémoires volatiles (~80 min hors tension), le clavier n'accuse jamais réception.
  5. Après restauration : re-dumper l'aire → le tableau de bord doit passer 🟢. Panel / Composer / Sequencer : restauration non validée (barée) tant que l'écriture n'est pas prouvée — voir la page outils.
  6. Écart 32 du bloc 40 (PANEL) : le clavier n'émet jamais les 32 derniers octets du bloc 40 (1056/1088 — écart systématique documenté). Il est normalisé depuis la v0.4.1 : le patch PANEL est accepté avec les octets connus (badge « écart 32 documenté »), et cet écart compte comme identique dans le tableau de bord. Toute autre perte réelle reste refusée.

🗂️ Bibliothèque (v0.5.0)

  • Dossier de travail : 📁 choisir un dossier local une fois — la page y écrit et relit tous les fichiers. C'est le même dossier que le Sound Editor : une seule arborescence pour tous les outils KN2000. Le dossier est retenu (IndexedDB) ; « oublier » le supprime. Sans l'API (Firefox, Safari), le bouton ouvre un sélecteur de dossier lecture seule : relire le master et importer fonctionnent depuis le dossier, les exports passent par téléchargements (session seulement, non mémorisé).
  • Master unique kn2000-master-v1 : « 💾 Écrire le master » exporte dans le dossier la vérité binaire complète — toutes les aires dumpées + les 36 sons (slot, nom, raw_hex) + meta. Fichier autonome, décodable par une future appli Android sans aucun localStorage. « 📖 Relire » recharge un master (patches par aire + sons, dédupliqués).
  • 🎛️ Panel Memories (24) : vue automatique des 24 PM (A1…C8, 336 o) extraite du bloc 41 du patch PANEL courant — même décodeur que la Panel Console (sons R1/R2/LEFT, rythme, tempo, APC, conductor, DSP ; survol = détail complet). La source (patch + date) est affichée ; PM incomplète = signalée. Ces PM entrent dans le master (section pms).
  • Importer (auto-détection) : un seul bouton reconnaît tous les formats du banc d'essai — master v1, catalogue kn2000-catalog-v1 (v0.3/v0.4), package/banque du Sound Editor (raw_hex 5184 o → patch Sound « PKG · nom » ; sans l'entête 80 o : restauration différentielle OK, complète impossible depuis le seul package), catalogue de sonorités ({sounds:[…]}) → bibliothèque de sons.
  • Sons nommés : bibliothèque personnelle, dédupliquée par contenu (identique = date mise à jour, différent = nouvelle entrée jamais écrasée). « ✉️ Envoyer vers le clavier » écrit le son choisi (144 o) dans le slot choisi (A-1…B-18) : 2 trames ITW, confirmation obligatoire — le clavier ne répond jamais, l'écran et le re-dump jugent. « ⬇️ Exporter » produit le format catalogue du Sound Editor ; « 📦 Exporter le patch Sound → package » produit un package 5184 o chargeable dans l'éditeur. La boucle backup ↔ éditeur est fermée sans ressaisie.

← Retour / Back

💡 This tool catalogs the keyboard's complete state through handshake bulk dumps (protocol validated on 2026-10-26 with Panel Console v1.0.9: exactly one ACK after every received packet), then exports a single timestamped JSON backup, decodable by a future offline Android app.

🚀 Quick start

  1. Open the page in Chrome, Edge or Firefox 108+ desktop (Web MIDI with sysex required).
  2. Plug the USB MIDI interface (e.g. Arturia MiniFuse) linked to the KN2000 by MIDI DIN cable — the KN2000 itself has no USB, click 🔄 Ports and pick In/Out.
  3. Plug the interface: the page tries to auto-connect with the memorized ports; otherwise pick In/Out then 🔌 Connect — the KN2000 is tested by a ping (DRQ 20 00 02) and the enables are read automatically once connected (read-only, nothing is written).
  4. Once the ● connecté badge shows: click 🔄 Dumper on the wanted area — the dump starts directly, no keyboard preparation needed (field discovery 2026-10-26: the keyboard's SYSEX BULK DUMP page does not need to be displayed).
  5. Once the wanted areas are cataloged, click 💾 Export the catalog (JSON).

🗺️ Areas (Reference Guide p.24-27) — all field-validated ✅

  • PANEL — ADR 40 00 00 — field-validated: blocks 40 (1056/1088, documented 32-byte gap) + 41 (8064/8064 = 24 Panel Memory × 336).
  • SOUND MEMORY — ADR 30 00 00 — field-validated: 80-byte header (block 30) + 36 sounds × 144 bytes (block 30#2, 5184/5184).
  • COMPOSER — ADR 50 00 00 — field-validated: 37,920 bytes (70 patterns).
  • SEQUENCER — ADR 60 00 00 — field-validated: 3 blocks (256 + 768 + 2048 bytes with content).
💡 Field discovery 2026-10-26: dumps start directly from the page — the keyboard's SYSEX BULK DUMP page does not need to be displayed, no type to select. "▶ Chain remaining areas" pauses 5 s between areas.
⚠️ The dump request uses the panel-validated form (ADR + SIZ 00 00 42): all 4 areas answer correctly with this constant (field-validated 2026-10-26).

🤝 Protocol

Same as Panel Console v1.0.9 (field-validated): DRQ → keyboard sends HRQ (21) → we answer HRT (22) → keyboard sends HRT (22) → we ACK, then exactly one ACK (f0 50 23 7e f7) after every received packet: BTR (2D), each checksum-OK CDD packet (7E), EOK (27), END (28). No automatic re-DRQ — a stray re-DRQ restarts the BULK DUMP page and breaks the handshake.

📄 Exported JSON format (kn2000-catalog-v1)

The file kn2000-catalogue-YYYY-MM-DD_HHhMM.json is self-documented (encodage field) and designed for an Android app:

  • data holds the original de-nibbilized bytes (they travel nibbilized ×2 on the wire — Reference Guide p.22); siz_annonce counts original bytes.
  • A missing byte (lost packet or block closed before SIZ) is written --: the string always keeps 2 × siz_annonce characters, byte index = char_index / 2.
  • Multiple blocks at the same address: an area may contain several blocks with the same adr (e.g. Sound Memory: 80-byte header then the 5184 sounds, both adr: "30") — the seq field (1, 2, …) gives the arrival order.
  • Android decoding example: int b = Integer.parseInt(data.substring(i*2, i*2+2), 16); — "--" ⇒ unknown byte.
💡 The panel's block 40 always stops at 1056/1088 bytes (constant 32-byte gap seen on every capture and in the field, harmless): the 32 missing bytes appear as -- in the JSON — this is normal.

Section 3 — Import catalog & send reloads a JSON exported by the page (kn2000-catalog-v1) and writes a chosen block to the keyboard, then verifies with a byte-per-byte diff.

  1. 📂 Import the catalog (JSON), pick the area and block.
  2. ✉️ Send: two modes — 36 sounds (each 144-byte sound goes as 2 ITW frames of 120 + 24 bytes at addresses 30 00 50 + n×90) or N-byte frames at a linearly incremented base address (default 30 00 50, N = 120 max, adjustable pace).
  3. Watch the keyboard's answers (log) — first real bulk write, unknown behaviour: ACK? silence? ERR?
  4. Wait ~5 s, 🔄 re-dump the area, then 🔍 Compare (byte-per-byte diff imported block vs re-dump).

Write frame ITW (2C) — mirror of the keyboard's ITRs, Sound Editor format. Field limit (bisection 2026-10-26): max 120 original bytes per frame (255 bytes on the wire — 256-byte keyboard buffer; 121+ refused, the keyboard answers NOTHING, it applies silently): f0 50 2c 01 18 10 A1 A2 A3 00 Sh Sl <nibbles> 00 CK f7 — 3×7-bit SIZ (original bytes), nibbilized ×2 data (Reference Guide p.22), CN = 00, CK = body XOR & 7f. The Sound Editor wrote byte-per-byte (60 ms); the test's unknown is the keyboard's reaction to multi-byte frames.

⚠️ Sending is a real write into the keyboard's memory. Recommended test on Sound Memory (recoverable through the factory procedure). A block containing missing bytes (--) is refused.

📚 Catalogue & restore (v0.4.0)

  1. 💾 Catalog (Dumps tab): the latest dump of an area becomes a catalog patch — automatic name + date. Content identical to the previous patch → only its date is updated; content different → new version. Old versions are never overwritten (explicit 🗑 deletion only).
  2. Dashboard (Catalogue tab): per-area crossing between what resides in the KN2000 (latest dump, persisted) and what should go there (current patch): 🟢 matching / 🟡 N bytes differ / ❌ never dumped — plus the date of the last send to the KN2000.
  3. 📂 Import a catalog: each area of a kn2000-catalog-v1 JSON becomes a (content-deduplicated) patch. Header info (blocks, sizes) and, for Sound Memory, the 36 sound names are shown under each Sound patch.
  4. ↩️ Restore (Sound Memory, ✅ field-validated): Full = 80-byte header + 36 sounds in 73 ITW frames (max 120 bytes/frame, 60 ms pace ≈ 5 s); Differential = send only the sounds/header that differ from the latest dump. Mandatory confirmation — volatile memories (~80 min unpowered), the keyboard never acknowledges writes.
  5. After a restore: re-dump the area → the dashboard must turn 🟢. Panel / Composer / Sequencer: restore not validated (greyed out) until writing is proven — see the tools page.
  6. Block 40's 32-byte gap (PANEL): the keyboard never emits the last 32 bytes of block 40 (1056/1088 — documented systematic gap). Normalized since v0.4.1: the PANEL patch is accepted with the known bytes ("documented 32-byte gap" badge), and the gap counts as identical in the dashboard. Any other real loss is still refused.

  • Import (auto-detection): one button recognizes every workbench format — master v1, kn2000-catalog-v1 catalogue (v0.3/v0.4), Sound Editor package/bank (raw_hex 5184 B → "PKG · name" Sound patch; without the 80-byte header: differential restore OK, full restore impossible from the package alone), sound catalogue ({sounds:[…]}) → named-sound library.
  • Named sounds: personal library, content-deduplicated (identical = date updated, different = never-overwritten new entry). "✉️ Send to keyboard" writes the chosen sound (144 B) into the chosen slot (A-1…B-18): 2 ITW frames, mandatory confirmation — the keyboard never replies, the screen and the re-dump judge. "⬇️ Export" produces the Sound Editor catalogue format; "📦 Export Sound patch → package" produces a 5184-B package loadable in the editor. The backup ↔ editor loop is closed with no re-typing.
